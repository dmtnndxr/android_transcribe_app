# План развития Offline Voice Input+

Состояние на 1 октября 2026, версия 0.1.21.

Распространение: **только GitHub Releases**. Платные площадки и площадки с ручной
проверкой (Google Play, Samsung Galaxy Store, основной F-Droid) пока не
рассматриваем. Бесплатно и без проверки добавить можно только ссылку для
Obtainium в README (этап 3).

Этапы идут в рекомендуемом порядке. Скриншоты и ролики стоит снимать **после**
этапов 1 и 2: история и уведомления меняют интерфейс, иначе их придётся
переснимать.

## Этап 1. Текст не теряется: буфер обмена и уведомление

**Проблема.** Долгая диктовка распознаётся и обрабатывается заметное время.
Если за это время свернуть приложение или переключиться на другое поле, вставить
текст некуда. Сейчас клавиатура держит его в памяти (`pendingCommitText`) и
вставляет, только когда снова откроется какое-нибудь поле ввода. Если система
выгрузит клавиатуру, текст пропадёт. Пользователь не видит, где его текст.

**Как должно работать.**
1. Распознавание закончилось, а поле ввода, где начинали, уже не активно
   (приложение свёрнуто, фокус ушёл, другое приложение).
2. Текст (после AI-очистки, если она была) копируется в буфер обмена.
3. Появляется уведомление в шторке «Транскрипция скопирована в буфер» с началом
   текста и кнопками **«Копировать снова»** и **«Открыть в истории»**.
   Если приложение на экране, достаточно короткого всплывающего сообщения.
4. Текст в любом случае сохраняется в историю (этап 2), поэтому не теряется,
   даже если пользователь уже скопировал в буфер что-то другое.

**Что учесть.**
- [ ] Как определять «вставить некуда»: `inputActive == false`, нет
      `InputConnection`, или поле другое, чем при старте записи (сравнивать
      `editorGeneration` или пакет приложения из `EditorInfo`). Вставка в
      *другое* поле — частая неприятная ошибка, буфер обмена здесь безопаснее.
- [ ] Решить, оставлять ли старое поведение «вставить, когда вернусь в поле».
      Предложение: оставить как настройку, а по умолчанию использовать буфер
      и уведомление. Это предсказуемее.
- [ ] Запись в буфер обмена из клавиатуры разрешена. На Android 13+ система
      сама показывает всплывающее подтверждение копирования, не дублировать его
      своим сообщением.
- [ ] Пометить содержимое буфера как конфиденциальное
      (`ClipDescription.EXTRA_IS_SENSITIVE`), чтобы система не показывала
      текст в превью. Сделать это отключаемой настройкой.
- [ ] Уведомления: разрешение `POST_NOTIFICATIONS` уже объявлено, но на
      Android 13+ его нужно запросить. Сделать отдельный канал уведомлений
      «Готовые транскрипции», чтобы его можно было выключить отдельно от
      субтитров.
- [ ] Тот же сценарий для распознавания через микрофон другой клавиатуры
      (`VoiceRecognitionService`): если приложение, которое запросило
      распознавание, уже закрыто, результат тоже должен попасть в буфер и
      историю.
- [ ] Чтобы долгую обработку не прервала система, пока клавиатура скрыта,
      рассмотреть короткую foreground-службу на время распознавания и
      AI-запроса.

## Этап 2. История транскрипций

**Что хранить** (только на устройстве):
- аудио записи;
- распознанный текст;
- текст после AI-очистки или правки, с пометкой режима (очистка / правка
  выделения / без обработки) и модели;
- время, длительность, модель распознавания, куда ушёл текст (вставлен / буфер
  обмена / отменён / ошибка) и сообщение об ошибке.

**Экран истории.**
- [ ] Список: дата, начало текста, длительность, значок результата.
- [ ] Карточка: проиграть аудио, показать исходный и обработанный текст,
      скопировать, поделиться, удалить.
- [ ] **Распознать заново** другой моделью и **обработать заново** через AI.
      Это полезно, когда распознавание или AI ошиблись.
- [ ] Поиск по тексту.

**Настройки и приватность.**
- [ ] Включение и отключение истории; отдельно — хранить ли аудио.
      Предложение по умолчанию: текст хранить, аудио хранить 7 дней.
- [ ] Срок хранения (день / неделя / месяц / всегда) и ограничение по объёму.
      Для оценки: 16 кГц моно 16 бит — около 1,9 МБ на минуту. Если сжимать
      (Opus/AAC), будет примерно в 10 раз меньше.
- [ ] Кнопка «Очистить историю».
- [ ] Всё лежит во внутреннем хранилище приложения и не попадает в резервные
      копии (`android:allowBackup` / правила `dataExtractionRules`), иначе
      надиктованное уедет в облако без ведома пользователя.
- [ ] Хранение: SQLite (Room или обычный `SQLiteOpenHelper`, как принято в
      проекте) плюс файлы аудио в `filesDir/history/`.
- [ ] Аудио сейчас живёт в Rust-ядре. Нужно отдать его в Java после записи или
      сохранить файл прямо в Rust (WAV, затем при желании сжать).
