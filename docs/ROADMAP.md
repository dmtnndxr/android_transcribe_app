# План развития Boice

Состояние на 5 октября 2026, версия 0.1.23 (первый выпуск под названием Boice).

Распространение: **только GitHub Releases**. Платные площадки и площадки с ручной
проверкой (Google Play, Samsung Galaxy Store, основной F-Droid) пока не
рассматриваем. Бесплатно и без проверки добавить можно только ссылку для
Obtainium в README (этап 3).

Этапы идут в рекомендуемом порядке. Скриншоты и ролики стоит снимать **после**
этапов 1, 2 и 3.6: история и онбординг меняют интерфейс, иначе их придётся
переснимать.

## Этап 1. Текст не теряется — сделано

**Проблема.** Долгая диктовка распознаётся заметное время. Если за это время
свернуть приложение или перейти в другое поле, вставлять текст некуда. Раньше
клавиатура держала его в памяти и вставляла в первое открывшееся поле — это
могло быть чужое поле, а при выгрузке клавиатуры текст пропадал.

**Как работает теперь.**
- [x] Текст вставляется сразу, только если открыто то же поле, где начинали
      запись (приложение + id поля из `EditorInfo`).
- [x] Иначе текст копируется в буфер обмена с всплывающим сообщением
      «Транскрипция скопирована в буфер обмена». Содержимое буфера помечено
      как конфиденциальное (`EXTRA_IS_SENSITIVE`), система не показывает его
      в превью.
- [x] Настройка «Копировать в буфер, если некуда вставить» (по умолчанию
      включена). Если выключена, при следующем открытии клавиатуры появляется
      плашка «Не вставлено: …» с кнопками «Вставить» и «Скрыть».
- [x] Если в течение минуты вернуться в то же поле, текст вставляется сам
      (веб-поля Firefox/Gemini иногда сами теряют фокус).
- [x] Результат правки голосом, если выделение успело измениться, тоже
      уходит в буфер, а не пропадает.
- [x] Микрофон другой клавиатуры (`VoiceRecognitionService`): если
      приложение, которое просило распознавание, уже закрыто, текст уходит
      в буфер.
- [x] Уведомления решили не делать: лишнее разрешение и лишний шаг на
      онбординге.

**Заодно.**
- [x] «Отменить» после обычной диктовки убрано, осталось только после правки
      голосом (она заменяет исходный текст).
- [x] Палочка правки: три состояния (контур + «Выделите текст» / заполненная
      «Изменить» / яркая «Стоп») вместо полупрозрачности; круглый эффект
      нажатия у палочки и кнопки «Диктовка с ИИ».

**Осталось.**
- [ ] Если клавиатура-клиент (Gboard) сама отменяет распознавание при
      сворачивании, запись выбрасывается в Rust-ядре. Решить, нужно ли
      дораспознавать её в этом случае.
- [ ] Текст, ожидающий вставки, живёт только в памяти клавиатуры. Закроется
      историей (этап 2).
- [ ] «Tap to Record» дублируется в строке статуса и под кнопкой.

## Этап 2. История транскрипций — основа сделана

**Что хранится** (только на устройстве, в SQLite `history.db` и
`filesDir/history/*.wav`): запись, распознанный текст, итоговый текст (после
ИИ или правки), для правки — выделенный текст «было» и команда, источник
(диктовка / с ИИ / правка / другая клавиатура), длительность, куда ушёл текст
(вставлен / в буфере / не вставлен / без изменений / ошибка / отменено) и
причина ошибки.

**Сделано.**
- [x] Карточка «История» на главном экране и экран истории: список с датой,
      источником, длительностью и пометкой, если текст ушёл не в поле.
- [x] Раскрытая запись: полный текст с выделением кусочков, «Распознано»,
      «Было», «Команда», причина ошибки; кнопки-иконки ▶/■, копировать,
      поделиться, удалить.
- [x] Поиск по тексту.
- [x] Настройки (⚙): сохранять историю, сохранять записи, срок хранения
      записей (всегда / 1 / 7 / 30 дней, по умолчанию всегда), занятое место;
      «Очистить историю» в меню.
- [x] Rust-ядро сохраняет WAV при остановке записи (около 2 МБ на минуту).
- [x] Записи во внутренней памяти приложения: плееры и галерея их не видят.
      История исключена из облачных копий и переноса на новый телефон.

**Осталось.**
- [ ] **Распознать заново** другой моделью и **обработать заново** через ИИ.
- [ ] Записи для микрофона другой клавиатуры (`VoiceRecognitionService`):
      сейчас сохраняется только текст.
- [ ] Сжатие записей (Opus/AAC — примерно в 10 раз меньше WAV).
- [ ] Название модели распознавания в записи.
- [ ] Плашка «Не вставлено» и автовставка живут только в памяти клавиатуры;
      можно показывать последнюю невставленную запись из истории.

один раз; «Run setup again» на главном экране. Карточки главного экрана

Тексты на английском и русском.

**Осталось:** переводы мастера на de, es, fr, it, pt; сворачивание блока
настройки в «Готово ✓»; кнопка из «ИИ не настроен» на клавиатуре в шаг мастера;
проверить клавиатуру Samsung.


**Проблема.** Сейчас новый пользователь видит главный экран со всеми настройками
сразу, а объяснение, какая клавиатура как работает, спрятано в длинном тексте
за кнопкой «Setup help». Что такое AI-очистка и правка голосом, не объясняется
нигде, кроме экранов их настроек.

**Что упростить нельзя** (ограничения Android, а не приложения):
- Включить свою клавиатуру за пользователя нельзя: он сам ставит переключатель
  в системных настройках. Можно только открыть нужный экран и дождаться
  возврата.
- Назначить себя распознавателем речи по умолчанию тоже нельзя: пользователь
  выбирает приложение в системном диалоге и жмёт «Всегда».
- Разрешение на микрофон — системный диалог.

**Что упростить можно.** Главное: показывать только тот путь, который подходит
клавиатуре пользователя, вместо общей справки про все клавиатуры.

### Шаги мастера
- [ ] **1. Приветствие.** Одна фраза о том, что это, и что звук не покидает
      телефон.
- [ ] **2. Микрофон.** Объяснение и системный запрос разрешения.
- [ ] **3. Способ ввода.** Определить текущую клавиатуру
      (`Settings.Secure.DEFAULT_INPUT_METHOD`) и показать один из путей:
  - **SwiftKey, AnySoftKeyboard** — микрофон клавиатуры открывает нашу панель.
    Шаг: нажать «Попробовать», выбрать приложение, «Всегда».
  - **HeliBoard, FlorisBoard, OpenBoard, Fossify, Unexpected** — их микрофон
    переключает на нашу клавиатуру. Шаг: включить нашу клавиатуру.
  - **Gboard** — с приложением не работает совсем: его микрофон всегда
    запускает голосовой ввод Google. Шаг: прямо сказать об этом, включить
    нашу клавиатуру и показать, как на неё переключаться (кнопка клавиатуры
    на панели навигации, долгое нажатие на пробел). Предложить HeliBoard
    как бесплатную клавиатуру, чей микрофон ведёт в Boice.
  - **Клавиатура Samsung** — вероятно, так же, как Gboard: автор не нашёл в
    её настройках выбора голосового ввода (4 октября), но это не точно.

  - **Неизвестная клавиатура** — предложить оба варианта.
- [ ] **4. Включение нашей клавиатуры** (если нужна по шагу 3). Кнопка
      открывает системный экран; после возврата проверить
      `InputMethodManager.getEnabledInputMethodList()` и поставить галочку.
      Затем `showInputMethodPicker()`, чтобы показать, как переключаться.
- [ ] **5. Проба.** Поле ввода прямо в мастере: надиктовать фразу и увидеть
      результат. Если не получилось — подсказка, что именно не так.
- [ ] **6. AI-функции (необязательно).** Объяснить простыми словами с примером

    переводить или менять стиль.
  - **Правка голосом** — выделить текст, нажать палочку, сказать, что
    изменить.
  - Честно сказать о приватности: звук остаётся на телефоне, но **текст

### Настройка AI в мастере
Предложение: **не требовать** настройку AI перед началом работы. Основная
функция работает офлайн и без неё, а обязательный шаг с ключом API отпугнёт
тех, кому AI не нужен. Вместо этого сделать шаг необязательным, но быстрым:

- [ ] Готовые варианты серверов: Ollama, LM Studio, OpenRouter, OpenAI —
      подставляют адрес, остаётся ввести ключ и модель.
- [ ] Кнопка «Проверить соединение» с понятным сообщением об ошибке.
- [ ] Правка голосом уже берёт сервер и ключ из AI-очистки; в мастере
      настраивать её отдельно не нужно.
- [ ] Если AI не настроен, а пользователь нажал второй микрофон или палочку,
      показывать не просто «не настроено», а кнопку, ведущую в этот шаг.

## Этап 6. Изучить Wispr Flow (делает автор сам)

Wispr Flow — коммерческое приложение для диктовки с AI-обработкой. Цель —
понять, какие идеи стоит перенять. Что посмотреть и записать:

- [ ] Как обрабатывает текст: стиль в зависимости от приложения (мессенджер /
      почта / заметки), убирает слова-паразиты и самоисправления
      («в среду… нет, в четверг» → «в четверг»).
- [ ] Личный словарь: имена, термины, и как он пополняется.
- [ ] Заготовки (snippets): короткая фраза голосом раскрывается в длинный текст.
- [ ] Голосовые команды над текстом (наш аналог — правка выделенного).
- [ ] Шёпот и тихая речь.
- [ ] История, статистика, онбординг: как объясняют функции новичку.
- [ ] Скорость: сколько ждать от конца речи до вставки текста.
- [ ] Что платное, а что бесплатное, — где у бесплатного open source
      приложения преимущество.

Итог: короткий список «перенять / не нужно / уже есть» и новые задачи в этот
